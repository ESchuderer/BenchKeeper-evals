# Claude Code settings, permissions, sandbox, hooks and memory against BenchKeeper

Ticket: [#379](https://github.com/ESchuderer/BenchKeeper/issues/379). Docs read on 2026-10-27 from https://code.claude.com/docs (pages fetched as Markdown, index at https://code.claude.com/docs/llms.txt). All docs URLs below are under `https://code.claude.com/docs/en/`.

## Question

Which documented Claude Code settings, permission rules, sandbox options, hook events and memory features are missing from, outdated in or wrongly described by BenchKeeper's settings catalog, rules and security notes (`app/src/settings/`, `docs/security.md`, `app/src/rules.mjs`, `app/src/extensions.mjs`)? Ranked by value for a user who runs several repositories.

## Short answer

The catalog values and enums, the hook trust behavior, the memory limits, the import depth and the setup-token lifetime match the docs. The gaps are about security depth and scope handling, not about wrong values.

1. `permissions.blockReadsOutsideWorkingDirectories` and the sandbox hardening keys (`failIfUnavailable`, `allowUnsandboxedCommands`, `network.strictAllowlist`, `credentials`, `filesystem.denyRead`) are absent from the catalog, `couplings.json` and the project sandbox step. The claim in `docs/security.md` that reads of credential files stay open to the sandbox is outdated once Read deny rules or `credentials` are set.
2. Auto mode is the default and the docs say it allows pushes to any branch of the working repository, including the default branch, and PR creation. BenchKeeper adds no `permissions.ask` rule and `docs/security.md` lists none as a control.
3. Remote Control stores the session transcript on Anthropic servers while connected. Setup turns it on for every interactive session without saying so.
4. Instruction loading (`AGENTS.md` ancestors, managed `CLAUDE.md`, the `instructionFiles` option), managed settings delivery (drop-in folder, Windows, server cache), `CLAUDE_CONFIG_DIR` and the worktree location of `settings.local.json` are read differently from the docs. A multi-account or multi-worktree user sees wrong or missing rows.
5. The extensions inventory covers MCP, hooks, subagents, commands and styles, but not monitors, helper commands, claude.ai connectors or `mcp_tool`/`agent` hooks, and it shows project MCP approvals that Claude Code ignores in an untrusted folder.

## Outdated or wrong statements in BenchKeeper's docs and code

1. `docs/security.md:228`, `:262`, `:324`, `:328`, the `permissions.deny` catalog sentence and the `read-deny-credentials` message: credential reads stay open to the sandbox and a script that opens files itself is not covered. With the sandbox on, deny rules and `sandbox.credentials` do cover subprocesses (gap 4).
2. `app/src/extensions.mjs:118`: "the answer given in the approval prompt is stored where the documentation does not say". The docs name `.claude/settings.local.json` (gap 14).
3. `app/src/rules.mjs:151`: the memory folder encoding "is not documented". It is, with truncation and a hash (gap 20).
4. `app/src/rules.mjs:83-85`: `AGENTS.md` loads only when no `CLAUDE.md` exists in the project folder. The docs check ancestor directories too (gap 8).
5. `docs/security.md:271`: "what a remote input is checked against: unverified". The transcript storage part is documented, the permission part is still not found (gap 6).
6. Setup writes `cleanupPeriodDays: 14` (`steps/global.mjs:82`) while the catalog and `docs/setup.md` advise 30 or more. This is an internal inconsistency; the docs only state the default of 30 and that 0 fails validation ([settings-reference](https://code.claude.com/docs/en/settings-reference.md)).
7. `docs/security.md:157`: correct for `marketplace add`, incomplete for marketplace entries (gap 18).

Confirmed correct against the docs: the catalog values and enums for `defaultMode`, `theme`, `preferredNotifChannel`, `autoUpdatesChannel`; `attribution` `false` from v2.1.281; project and local `auto` and `bypassPermissions` ignored; hook timeouts do not block without `onFailure`; project hooks run in `claude -p` without a trust dialog ([hooks](https://code.claude.com/docs/en/hooks.md#security-considerations), [permissions](https://code.claude.com/docs/en/permissions.md#what-runs-before-you-trust-a-folder)); `MEMORY.md` 200 lines or 25 KB; import depth 4; `claudeMdExcludes` link-or-target match; the setup-token one-year lifetime ([authentication](https://code.claude.com/docs/en/authentication.md#generate-a-long-lived-token)); the `rate_limits` status line fields; the env scrub leaving GitHub tokens and proxy variables ([env-vars](https://code.claude.com/docs/en/env-vars.md#what-the-subprocess-environment-scrub-removes)).

Catalog coverage: 26 of 247 documented Claude keys are curated. The Advanced view exposes all 247 from `claude-settings-keys.json`, which matches the live settings-reference index on 2026-10-27 (same key set). The JSON schema file has 141 keys and lags, so `inSchema` is false for newer keys.

## Unverified

- Whether `claude auth status --json` is accepted as a flag. The docs list JSON as the default output and `--text` for text ([cli-reference](https://code.claude.com/docs/en/cli-reference.md)).
- Internal formats BenchKeeper reads without a documented contract: `installed_plugins.json` fields `gitCommitSha` and `version: 2`, `known_marketplaces.json`, the hash form of the project folder name, the `remote-settings.json` format.
- How a Read deny rule is translated into a sandbox `denyRead` entry (the docs say both sources are merged).
- How a remote-control input is checked against the permission mode, and whether mobile `/config key=value` is limited to some keys.
- Pages read only through excerpts and targeted sections, not in full: hooks (per-event input schemas beyond the first part), monitoring-usage, env-vars table, settings-reference per-key text, managed-settings, server-managed-settings, hooks-guide, costs, auto-mode-config rule sections. Pages not read: agent-sdk pages, hipaa-setup, zero-data-retention, claude-security, security-guidance, devcontainer, sandbox-environments (index only), claude-apps-gateway.
- Version numbers (`v2.1.xxx`) are taken from the docs text; I did not check them against the changelog.
- Behavior was read from the docs and the repository files only. No Claude Code session was run, so none of the claims were tested against the installed version.
- Out of scope: Codex, Gemini, Copilot and Orca claims.
